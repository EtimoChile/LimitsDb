| `DEC-021` | 2026-10-13 | `ACTIVE` | Operations/security | Replaces item (b) of `DEC-020`; (a) and (c) stay. When `ldb-run --mode EXECUTE` finds a history DDL delta and admin history credentials are absent, it executes the delta directly over the runtime HISTORY connection without pre-checking privileges (it works when the user owns the objects or holds `ALTER`). Any failed statement, whatever the cause, does not stop the rest. Without admin credentials, if the history schema cannot be inspected with the runtime connection, `ldb-run` logs the cause and exits 1 instead of running ILM blind (with admin credentials the admin path still applies). Every failed statement, preceded by its Oracle error as a comment, is written to `history_ddl_<schema>_<YYYYMMDD_HHMMSS>.sql` under the new `ddl_pending_dir` parameter (default `ldb_ddl_pending`, `--ddl-pending-dir`, `LDB_DDL_PENDING_DIR`); if at least one failed, `ldb-run` logs an error naming the file and exits 1 so a DBA can run it; if the file cannot be written, it logs the error with the failed statements and exits 1. The file is plain SQL for SQL*Plus (no PL/SQL): `whenever sqlerror exit failure` stops it at the first failing statement and a final `LimitsDb: OK` banner marks complete success. `ldb-run` never prints DDL to stdout. `DatabaseEngine` gains `execute_ddl_statements`. The parameter name avoids "script" to keep it apart from `--mode SCRIPT`. | Privilege pre-validation is costly and unreliable, so attempting the DDL and recording failures is simpler and safer; a file keeps DDL out of stdout/INFO logs and gives the DBA a reviewable artifact; the DDL autocommits, so only unapplied statements go to the file. | Builds on `DEC-020`; `PEND-017` keeps covering `ldb-impl` for the base objects. | `README.md` § Admin credentials in ldb-run; `limitsdb/core/ldb_runner.py` (`_ensure_history_tables`, `_write_pending_ddl`); `limitsdb/core/ldb_params_config.py` (`ddl_pending_dir`); `limitsdb/db/ldb_engines.py` and `limitsdb/db/oracle/ldb_engine_impl.py` (`execute_ddl_statements`) | changelog: `ldb-run` without history admin credentials now applies pending history DDL with its runtime connection; statements that fail are written to `ddl_pending_dir` (`--ddl-pending-dir`) for a DBA and the run exits 1. |
