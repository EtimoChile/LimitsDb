# Compact decision register

This register avoids reopening already-decided alternatives. It summarizes
durable decisions and points to the artifact that publishes or implements them.
It does not duplicate specifications or record every code change.

| `DEC-002` | 2026-10-05 | `ACTIVE` | Architecture | Keep the core engine-independent and encapsulate Oracle under `limitsdb/db/oracle/`; every common capability originates in `DatabaseEngine`. | Preserve the declared extension to other engines without leaking Oracle details into the domain. | Current architectural contract. | `AGENTS.md`; `limitsdb/db/ldb_engines.py` |

| `DEC-004` | 2026-10-05 | `ACTIVE` | Management/agents | Use `AGENTS.md` as the only constitution and keep `CLAUDE.md` as a minimal bridge without duplicated rules. | Avoid divergence between tool-specific instructions. | Related to `DEC-001`. | `AGENTS.md`; `CLAUDE.md` |
| `DEC-005` | 2026-10-05 | `ACTIVE` | Identity/API | Rename the project to `LimitsDb`, the package to `limitsdb`, and the technical prefix to `ldb` / `LDB` across all public interfaces and owned objects. | Avoid collision with the TerminusDB project and express control over database growth. | Incompatible identity and public name change. | `README.md`; `pyproject.toml`; `CHANGELOG.md` |

| `DEC-010` | 2026-10-06 | `ACTIVE` | Tests/CI/security | Run automated Oracle integration on an ephemeral database inside a GitHub Actions Linux runner, without giving access to the persistent cloud database to external contributor code. | Allow real, reproducible Oracle tests with per-job isolation, without shared infrastructure secrets or residual state between contributions. | Advances `PEND-005`; applies `DEC-003`. | `.github/workflows/oracle-integration.yaml`; `tests/integration/test_oracle_ephemeral.py`; `README.md` |
| `DEC-011` | 2026-10-07 | `ACTIVE` | Configuration/multi-db | Maintain ILM policies exclusively in configuration files and retire `LDB_CNF` as a source and required object. The transition will not automatically delete existing legacy tables. | A single external configuration avoids replicating DDL, reading, and policy synchronization per engine and per database, and simplifies scenarios with source and history in different databases. | Related to `DEC-002` and `DEC-009`; originates `PEND-009`. | `docs/ai-state/PENDING.md`; future implementation in configuration, engine contracts, and `ldb-impl` |
| `DEC-012` | 2026-10-07 | `ACTIVE` | ILM/historical retention | Each archived row preserves the values needed to reevaluate in `HISTORY_ILM` all predicates considered in `SOURCE_ILM`, not just the one that produced the transfer. This includes all distinct cut-off dates and additional columns used by conditions, especially when sourced from related tables. `LDB_DATE_<suffix>` uses a date differentiator, not a SQL alias; predicates with an equivalent date share a column but retain their own filters and retention windows. For other related columns, the `<column>_<alias>` format does use the SQL alias to identify and disambiguate the origin. | A row applies ILM if any of its predicates is true and another condition may subsequently enable its historical disposition. The complete snapshot preserves the `OR` semantics without duplicating equivalent values or re-querying the source. | Clarifies the current design; related to `DEC-010`. | `README.md`; `limitsdb/core/ldb_runner.py` |
| `DEC-013` | 2026-10-07 | `ACTIVE` | Configuration/operational security | `use_added_columns` and `add_ldb_columns` are defined only in the persistent environment configuration. They are not exposed as specific flags, environment variables, or keys modifiable through `--set`. Other environment variables are authorized and mapped by the exact name declared in `Env(...)`, always under the public `LDB_` prefix. | Altering the historical structure between runs can leave the environment unstable; an explicit register prevents any `LDB_*` name from accidentally becoming configuration. | Related to `DEC-009`; resolves `PEND-011`. | `README.md`; `docs/configuration-contract.md`; `limitsdb/core/ldb_params_config.py`; `limitsdb/core/ldb_config_loader.py` |
| `DEC-014` | 2026-10-07 | `ACTIVE` | Engines/configuration | Accept only `oracle` as `db_engine` while it is the only implemented adapter. PostgreSQL remains a future extension and `postgres` is rejected in CLI, configuration validation, and direct engine loading before attempting a connection. | Do not announce a non-existent capability as selectable and fail early with an unambiguous diagnostic, without abandoning the engine-independent contract. | Resolves `PEND-007`; related to `DEC-002`. | `README.md`; `limitsdb/core/ldb_params_config.py`; `limitsdb/db/ldb_engine_loader.py`; `CHANGELOG.md` |
| `DEC-015` | 2026-10-07 | `ACTIVE` | Tests/coverage | Measure line and branch coverage combining the local suite and the Oracle E2E suite in the ephemeral runner, including entry points run as subprocesses and multiprocess workers. Publish reports as an artifact and do not enforce a minimum until the first combined baseline is verified. | A measurement limited to the `pytest` process would omit central paths of `ldb-impl`, `ldb-run`, and `ProcessPoolExecutor`; a threshold without a baseline could become an arbitrary barrier. | Related to `DEC-007` and `DEC-010`; originates `PEND-013`. | `pyproject.toml`; `.github/workflows/oracle-integration.yaml`; `README.md` |
| `DEC-016` | 2026-10-07 | `ACTIVE` | ILM/relationships | `source_orphan_purge` transfers to history source rows with no relationship: uses `left outer join`, considers a row orphaned when any `orphan_check_column` is null, persists that state in `LDB_IS_ORPHAN`, and replaces with the process date any related control date that evaluates to null. Requires `use_added_columns` and positive historical retention to preserve those values and later apply the configured retention. | The orphan must be preserved in history, but no longer has the related row needed to reevaluate its predicates; persisting its state and a stable fallback avoids both direct deletion and a subsequent dependency on the source or its filters. | Resolves `PEND-010`; related to `DEC-012`. | `README.md`; `limitsdb/resources/ilm.example.yml`; `limitsdb/core/ldb_runner.py`; `limitsdb/db/ldb_engines.py` |
| `DEC-017` | 2026-10-09 | `ACTIVE` | Security/CI | Protect `development` with required status checks (`quality`, strict), required PR review (1 approver, dismiss stale), and `enforce_admins: false`. CODEOWNERS requires review from `@etimochile` on all changes. Workflows declare `permissions: {}` at workflow level and `contents: read` at job level. | CODEOWNERS and per-job permissions reduce the blast radius of compromised tokens; PR review enables participation from authorized contributors; `enforce_admins: false` preserves owner action capability in emergencies. | Resolves `PEND-014`; prerequisite for `PEND-006`. | `.github/CODEOWNERS`; `.github/workflows/quality.yaml`; `.github/workflows/oracle-integration.yaml` |

This matches the language of `README.md` and the source code, and ensures a single language across the repository. | Avoid mixed-language navigation and ensure all contributors can read any file without switching languages. | Constitutional rule. | `AGENTS.md` § Language |
