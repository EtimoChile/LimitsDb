# Changelog

## [Unreleased]

## [0.8.0] - 2026-10-23

- Fix the release workflow publishing to TestPyPI with the wrong upload URL: it now uses `https://test.pypi.org/legacy/`.
- Fix three review findings of the runner: the lock connection is checked every 30 s of elapsed time even while workers keep finishing (before, only an idle wait checked it); `--mode PREVIEW` over a table already `TEND` for the date is refused with exit code 1 instead of exiting 0; and the visibility of every configured table is resolved before references are walked, so a child listed before its invisible parent is skipped too.
- **Breaking:** single-identifier parameters of the ILM configuration (`source_owner`, `history_owner`, `table_name`, and the entries of `referencing_tables`, `extra_select_tables` and `history_extra_select_tables`) are now the exact data dictionary names, taken literally. Before, the runner passed them through the engine's identifier normalization (Oracle: upper case, or quotes removed), so a mixed-case name needed quotes in the file. Remove any quotes: write `Gl`, not `'"Gl"'`. Expressions still follow the engine's SQL rules.
- Fix the runner start losing lock anchors: each `LDB_RUN_LOCK` anchor is committed on its own, so a lost insert race no longer rolls back the anchors created before it, and a lock query that returns no row stops the run instead of leaving a table unprotected.
- Fix history joins (`use_added_columns: false`) with quoted or case-sensitive names: the owner rewrite now belongs to the engine (`DatabaseEngine.rewrite_table_owners`), which matches quoted names exactly and keeps a case-sensitive history owner quoted.
- Fix the `from` clause of the generated queries lower-casing the table and owner, which could not reach an object with a case-sensitive name: it now renders them through the engine (`DatabaseEngine.format_identifier`).
- **Breaking for custom engines:** `DatabaseEngine` has two new abstract methods, `rewrite_table_owners` and `format_identifier`.
- Fix `ldb-run --mode EXECUTE` crashing with a traceback when another runner holds a table (ORA-00054): the refusal is now handled in the runner, logged once as an error and the process exits with 1; nothing is started. The message names the runner that holds the table (run id, mode, host, pid, start) and `Runner id` is logged only once the locks are taken.
- Make the STATUS session statistics an optional engine capability: `is_run_alive`, `check_monitoring_access` and `get_session_activity` now have defaults in `DatabaseEngine` (cannot tell / nothing offered), so other engines only implement the control-table reads.
- Change connection logging in the CLIs: a successful connection logs only `<description>: connected` (no dsn or user); a failed one logs the dsn and user (Oracle connection errors now name them, never the password).
- Add `ldb-run --mode STATUS [--last n]`: a read-only report, for SOURCE and HISTORY, of the current and the last `n` executions (PREVIEW runs are never shown). Each execution is `RUNNING`, `OK`, `ERRORS` or `PARTIAL` and shows its rows processed; each table line reads `OWNER.TABLE  status: TEND  rows processed: N, started: … finished: … elapsed …` followed by the action and process date from `LDB_CTL`; a running table also shows the progress and time left of its long operation, its current wait when significant, and its waits plus CPU in seconds up to 95% of the time. Whether a run is alive is verified by trying its `LDB_RUN_LOCK` row with `NOWAIT` and releasing it at once. The Oracle session views `gv$session`, `gv$session_longops`, `gv$session_event` and `gv$sess_time_model` are probed first; what the runtime user cannot read is read over the admin connection when one is configured; otherwise it is skipped and a script with the `GRANT` statements is written under `--ddl-pending-dir` for a DBA to run.
- **Breaking:** rerun `ldb-impl` after upgrading: it adds `LDB_CTL.CTL_DB_SESSION_ID` (the session of the worker, composed by the engine; Oracle RAC aware: `instance.sid.audsid`) and reinstalls `check_save_status`. `STATUS` rebuilds the executions from the `LDB_LOG` timestamps, so earlier log rows are reported too.
- **Breaking for custom engines:** `DatabaseEngine` has two new abstract methods, `get_log_entries` and `get_control_entries`; `check_monitoring_access`, `get_session_activity` and `is_run_alive` are optional and have defaults.

## [0.7.0] - 2026-10-22

- **Behavior fix:** a table with several `referencing_tables` is now purged only when every referenced table allows it. The conditions of one table remain alternatives (`or`) and the tables are combined with `and`; before, all conditions were combined with `or`, so a child moved as soon as any parent condition matched.
- **Breaking:** rerun `ldb-impl` after upgrading: it creates the table `LDB_RUN_LOCK`, adds to an existing control table the columns it lacks (`LDB_CTL.CTL_RUN_ID`) and reinstalls `check_save_status` (new `p_run_id` parameter) and `check_referencing_tables`.
- `ldb-run --mode PREVIEW` now writes its own `ldb_ctl` statuses, the `EXECUTE` ones prefixed with `P` (`PTSTART`, `PCSTART`, `PCEND`, `PLSTART`, `PLEND`, `PTEND`, `PERROR`), and ends each table with `PTEND`, so a PREVIEW no longer makes an `EXECUTE` of the same day skip the tables. A PREVIEW over a table with an `EXECUTE` status of the same day fails with `ORA-20006`. An `EXECUTE` continues an incomplete `EXECUTE` of the same day keeping its rows; anything else restarts the table and closes the abandoned run in `ldb_log` ("Incomplete process closed by a later process"). These rules live in PL/SQL, so they hold for `SCRIPT` too.
- A second `ldb-run` over a table already being processed stops with exit code 1 (`RunnerBusyError`) before starting any worker. Workers stop with `ORA-20005` if they lose the table to another runner, and `CSTART`/`CEND` now stop the worker when the control check fails.
- The LOB path of `SOURCE_ILM` now records `LSTART`/`LEND`. A failed table gets a single `ERROR` row: the one written by the block is not duplicated by the runner; failed tables report the rows really moved with the executed PL/SQL and the error is propagated.
- `ldb-impl` now fails (`ExecutionError`, exit code 1) when `t_referencing_tables`, `check_save_status` or `check_referencing_tables` are left invalid after installing them, because `CREATE OR REPLACE` does not raise on compile errors. The generated `SCRIPT` cannot detect it.
- The 5 s start guard now counts from the last chunk end and applies only to in-progress statuses, so a start between two chunks of a running block is rejected and an `ERROR` can be retried at once. `ldb_ctl` gets the column `CTL_RUN_ID` (rerun `ldb-impl`); each run, including a generated `SCRIPT`, has its own id and a run that lost its table stops with `ORA-20005`.
- **Breaking for generated scripts:** the `SCRIPT` mode no longer fixes the mode when it is generated. Run it as `@script EXECUTE|PREVIEW`; the process date variable is renamed `&process_date` -> `&ldb_process_date`.
- **Breaking for custom engines:** `sql_block_run` takes `mode` and `run_id`, `save_error_status` takes `run_id`, and `DatabaseEngine` has new abstract methods `get_resumed_rows`, `error_recorded_since`, `acquire_run_locks`, `check_run_locks` and `release_run_locks`; the STATUS mode adds `get_run_records`, `check_monitoring_access`, `get_session_activity` and `is_run_alive`.
- The "rows processed" count logged per table no longer subtracts the previous run's counter (the block restarts it at `TSTART`), so it no longer shows 0 when a PREVIEW counted the same rows before.
- **Breaking:** the `DRY_RUN` mode, a legacy alias of `PREVIEW`, is removed; use `--mode PREVIEW`.
- Without source admin credentials, `ldb-run` no longer warns on every run that the source grants are not applied; only privileges the runtime user really lacks are reported.
- `ldb-run --mode PREPARE` no longer writes table grants when the runtime user does not hold the role (they cannot fix it): it reports that the role is not enabled, points to `ldb-impl` (which grants it again) and stops with exit code 1 without checking anything else.
- **Breaking for custom engines:** `DatabaseEngine` no longer has `generate_table_structure_script`, `execute_ddl_statements`, `generate_table_privilege_script` or `generate_bootstrap_script`. Every `ensure_*` method now takes an optional keyword `ddl_sink`; when given, the engine hands it the DDL instead of executing it (a `None` connection then means nothing is read from the database). `ensure_table_structure` and `ensure_table_privileges` also take `ddl_failures`: with it, statements that fail are collected with their error and the rest still run. `ensure_table_structure` and `ensure_table_privileges` no longer return the generated statements.
- `ldb-run` and `ldb-impl` deliver their DDL through the `ensure_*` methods; their behavior and generated files are unchanged.
- The `ldb-impl` bootstrap script asks once for the runtime user's password and reuses it to reconnect for the database link, instead of asking twice.
- `ldb-impl` now logs which runtime user rejected the configured password (an existing user keeps its password) and exits 1, instead of failing with the generic connection error; the bootstrap script prints the same hint before reconnecting. New `InvalidCredentialsError`, a `DatabaseConnectionError` subclass that `get_connection` raises for ORA-01017.
- The `ldb-impl` bootstrap script now asks for every password at its start, before it changes anything. `DatabaseEngine` has a new abstract method, `script_password_prompts`, which a script calls first.
- Fix `ldb-run` without history admin credentials failing with ORA-00942 while applying history grants: existing table grants are now read from `all_tab_privs` on runtime connections, keeping `dba_tab_privs` on admin connections.
- **Breaking for runtime usernames in lowercase:** `source_username` and `history_username` are data-dictionary names. A lowercase name (`ldb`) is a quoted user created as `"ldb"`, and the runtime login now quotes it the same way, so it no longer logs in as `LDB`. A regular user stored in uppercase (`LDB`) must now be configured as `LDB`. Admin usernames are used as configured.
- Fix `ldb-impl` for lowercase users: the quota DDL quotes the user, the quota lookup binds the tablespace as the dictionary stores it, and the bootstrap script looks the user up in `dba_users` under its own name.
- `ldb-run` no longer fails with `KeyError` when the runtime user cannot see a table: a table with no visible columns, or that references one, is skipped with a warning. `--mode SCRIPT` now applies the source grants when it has source admin credentials (and writes no `source_grants` file), and every mode warns when source admin credentials are absent.
- Add `ldb-run --mode PREPARE`: it applies the source grants (or, without source admin credentials, writes them to `ddl_pending_dir` only for the tables the runtime user cannot see) and the history DDL and grants without running ILM, and exits 1 if the runtime user cannot see a configured table. Run it before `SCRIPT`, `PREVIEW` or `EXECUTE`.
- `VALIDATE` and `PREPARE` check the table privileges the runtime user receives through its source and history roles (and that the roles are enabled); `PREPARE` writes only the grants that are missing, and the other modes warn about the gaps. **Breaking for custom engines:** `DatabaseEngine` has two new abstract methods, `get_missing_table_privileges` and `is_role_enabled`.
- `HISTORY_ILM` joins with `use_added_columns: false` now read the history owner of each table in `referencing_tables` instead of the source owner. New rule fields `extra_select_tables` and `history_extra_select_tables` list tables read by filter subqueries; their role gets `SELECT` on them in `ldb-run`, `--mode PREPARE`, `--mode SCRIPT` and the privilege checks. History falls back to `extra_select_tables`. A `TABLE@SRC` read needs the table in `extra_select_tables`.

## [0.6.0] - 2026-10-14

- `ldb-run` without history admin credentials now applies pending history DDL with its runtime connection; statements that fail are written to `ddl_pending_dir` (`--ddl-pending-dir`) for a DBA and the run exits 1.
- `ldb-impl` no longer requires admin credentials: when they are absent it writes a rerunnable SQL*Plus bootstrap script per database under `ddl_pending_dir` for a DBA, creating the database link as the runtime user. The script prompts for passwords with hidden input and warns when a user already exists, because its password is left unchanged.
- `HISTORY_ILM` without admin credentials now reaches the runtime-connection path.
- Document that `PREVIEW` applies the same DDL and grants as `EXECUTE` and skips only the data movement, because a run needs the objects in place.
- Replace a primary key with a single `DROP PRIMARY KEY DROP INDEX` statement so the generated DDL no longer fails with ORA-01418.
- Read primary-key and index metadata from `all_*` dictionary views on non-admin connections, keeping `dba_*` on admin connections.
- `--mode SCRIPT` now writes the history table DDL and the table grants to files under `ddl_pending_dir` and applies nothing; the ILM script stays on stdout. Without history admin credentials `ldb-run` also applies the history grants over its runtime connection, and any statement or grant it cannot apply goes to the pending file. The new `history_baseline` option (`--history-baseline`, `LDB_HISTORY_BASELINE`, default `EMPTY`) chooses whether to assume an empty history or one with the same objects as source when history cannot be read.
- Add the `ddl_pending_dir` option (`--ddl-pending-dir`, `LDB_DDL_PENDING_DIR`, default `ldb_ddl_pending`) for the files that `ldb-run` and `ldb-impl` write for a DBA.
- **Breaking for custom engines:** `DatabaseEngine` has four new abstract methods, `generate_table_structure_script`, `execute_ddl_statements`, `generate_table_privilege_script` and `generate_bootstrap_script`.

## [0.5.0] - 2026-10-10

- Archive source orphans selected by `left outer` joins and `orphan_check_column IS NULL`, snapshotting `LDB_IS_ORPHAN` and the process date whenever a related retention-date expression is null so historical retention remains evaluable.
- Reject PostgreSQL as a configured database engine until its adapter exists; Oracle is the sole accepted engine in configuration, CLI help, and engine loading.
- Make `Env(...)` metadata authoritative for environment overrides, normalize the ILM file variable to `LDB_ILM_CONFIG_FILE`, and keep history-column shape settings file-only by rejecting environment and `--set` overrides.
- Preserve related-table columns used only by historical filters and rewrite those predicates to their stored `<column>_<alias>` snapshots during `HISTORY_ILM`.
- Generate source-to-history inserts with one explicitly aliased value for each `LDB_PROCESS_DATE` and `LDB_INSERT_DATE` audit column.
- Avoid double-counting processed rows when chunk totals have already been recorded before the table reaches `TEND`.
- Route `HISTORY_ILM` reads and deletes through the configured history owner, and size control/log action fields for the full `HISTORY_ILM` value.
- Use stored relationship-derived columns during `HISTORY_ILM` instead of joining history cleanup queries back to source tables.
- Restore completed-run status from `LDB_CTL` when policies come from YAML, so same-day reruns remain idempotent and launch no workers.
- Add isolated Oracle adapter integration tests backed by an ephemeral Oracle Database Free container in GitHub Actions with generated, masked per-job credentials; cover recovery after partial DDL, idempotent object and privilege administration, and an end-to-end source/archive/history ILM happy path; characterize runner dependencies and progress-based retry behavior.
- Preserve the documented configuration precedence from system and user files through explicit overlays, environment variables, CLI values, and encrypted secrets; map names such as `LDB_CHUNK_SIZE` to their flat Python keys; add immutable execution, connection, administration, and runtime-context views without changing the public flat configuration; and type normalized ILM rules and derived table state.
- Add chained domain errors for configuration, secrets, validation, database connections, and execution; fail closed on unreadable secret files; and make worker failures recoverable by the coordinator.
- Replace YAPF, Flake8, and Pyright with a unified Ruff formatter/linter profile, retain strict mypy as the type-checking authority, and add reproducible pre-commit and CI quality gates.
- **Breaking:** rename the project and Python package from `TerminusDB` / `terminusdb` to `LimitsDb` / `limitsdb`, and replace the `tdb` / `TDB` prefix with `ldb` / `LDB` across CLI commands, environment variables, local paths, configuration keys, generated columns, and Oracle control objects.
- **Breaking:** retire `LDB_CNF` and `LDB_CNF_ID`; ILM policies are now loaded exclusively from configuration files (`LDB_ILM_CONFIG_FILE` or the default path).
- Use dedicated `LDB_CTL` and `LDB_LOG` tables to track process control metadata and provide end-to-end traceability.
- Process independent tables in parallel using a configurable worker pool (`--parallel-max` / `LDB_PARALLEL_MAX`, default 10); tables with dependencies are sequenced automatically across execution stages.
- Basic CLI module (`ldb-init`, `ldb-crypt`, `ldb-run`, `ldb-impl`).
- Encrypt database credentials at rest using AES-256-GCM; `ldb-run` and `ldb-impl` automatically encrypt any plaintext secrets in `secrets.json` at startup before the first ILM run; `ldb-crypt` encrypts them in advance without executing ILM; the per-user key is stored in `~/.limitsdb/ldb.key` (or `LDB_MASTER_KEY`).
- Centralized Config definition with defaults, YAML configurations, CLI, and environment variables.
- Improved logger to include process and thread names.
